# 可行性评估：语义校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围与评审责任

对应 `Feasibility review` 对是否值得且能够进入开发的判断，依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)及[生命周期模型](../../../wish_to_product.sysml)，遵循[公共规范](../README.md)。输入为选定 Wish/上下文、概念方案、约束/假设、研究或试验观察、成本风险、结构结果及问题；workflow 配置的人或 AI AGENT 提交实际理由和决定。此文档只规定目标标准。

允许评价可行性、提出范围调整和验证关键假设；输出为当前范围的可行性结论与继续/等待/返工建议，形成新的开发记录。旧发布保持只读；成果发布见[项目发布语义规则](../project_release/semantic_constrains.md)。

## 规则

| ID | 工程判据 | 评审证据 |
| --- | --- | --- |
| FEAS-SEM-001 | 候选概念对应 Wish 的真实预期结果、使用情境和限制，可解释为何进入开发能推进该意图。 | Wish、澄清及概念方案 |
| FEAS-SEM-002 | 可行性比较关注真正影响选择的技术、资源、成本和风险；初步估计说明不确定性，不把未经验证的数字视为承诺。 | 比较、估计依据、限制 |
| FEAS-SEM-003 | 关键假设有可信依据或可执行核实计划，失败后的影响明确；决定性前提缺失时不能用“以后解决”代替支持。 | 假设、观察、核实计划 |
| FEAS-SEM-004 | 现有 Pilot/xdesign 能力与待建设产品能力清楚，语言解析、工具安装、模型声明不能证明关卡调度、持久恢复或验收已经具备。 | 现有实现、试验结果、能力差距 |
| FEAS-SEM-005 | 首版范围可实现，所选概念保持本地模块与明确接口等设计边界；后续平台扩展不无理由成为首版前提。 | 范围、概念与依赖 |
| FEAS-SEM-006 | 人/AI AGENT、用户修改开发决定、独立 Wish 链、原生 view、历史恢复、固定工具绑定与开发/不可变发布隔离有可行的接入方向；核心目标没有被删去以形成表面可行。 | 核心能力方案、差距与风险 |
| FEAS-SEM-007 | 成本和资源足以开展下一阶段，关键依赖可取得或有说明的替代；授权和工具条件与实际工作环境相容。 | 资源/工具依据、接入条件 |
| FEAS-SEM-008 | 风险与未解决问题的影响、责任和处理路径足以支持继续建议；例外只限有依据的范围，保留反证和不确定性。 | 风险、问题、处置建议 |
| FEAS-SEM-009 | 对自举，首次最小引导机制有明确有限来源及固定工具/依赖选择，后续规则或工具候选依据起始选择评价；用户规则可由后续新尝试显式采用，工具成果封存为 T2 供新项目使用，不自动替换既有 T1。避免以目标系统尚未具备的能力证明自身可行。 | 引导方案、固定工具/引导选择、验证路径 |
| FEAS-SEM-010 | 继续理由限定当前 Wish/增量进入开发的可行性，不等价于 SRR/PDR/CDR 通过；上游假设进入后续需求与验证的可追溯准备。 | 结论范围、后续假设与计划 |
| FEAS-SEM-011 | 概念应可信地支持固定 T1 与可变用户约束的划分，正常保存只写开发资产，候选固定后能独立于继续编辑，失败封存不会生成成功发布，旧发布能保留完整确定依赖并用原 T1 读取。工具更新不成为当前项目日常阶段的隐式前提。 | 工具/项目边界方案、候选与封存设计方向、依赖保存及读取能力依据。 |
| FEAS-SEM-012 | R1 后修改约束、模型、文档和开发决定再创建 R2，R1 内容/决定/依赖不变且仍可用原 T1 读取/展示，是当前架构核心目标，应有可行的接入及后续验证路线。缺少既有能力时明确建设与风险，不把概念方案或单次试验当作该完整场景已获证明。 | 发布隔离路线、核心风险、原 T1 读取依据、后续需求与验证准备。 |

## 出口与返工

保存逐项支持和缺口，形成 `Feasibility review` 的建议及有效决定。可行性不足时补研究/试验或调整范围，意图不清回澄清，等待状态按外层流程处理。批准仅准许 `development`，后续十阶段独立生产材料和判断；用户替代决定新增开发记录，保留原不足与下一工作的限制，不改旧发布；早期研究/试验保留原输入与规则，复用须论证对当前选择仍适用。
