# 退役与归档的语义充分性约束

规则集版本：0.1。日期：2026-10-12。状态：目标规范；评审要求不声明已有停用、资源处置、归档或知识转移事实。

## 适用范围、依据与输入

适用于 `RetireProduct` 的退役准备、`Retirement authorization` 的前置授权判断和 `DecommissionAndArchive` 产出证据的充分性评价。依据[生命周期源模型](../../../wish_to_product.sysml)、[V-model 的 ReviewAgent](../../../v_model_agents.sysml)及[整体架构设计 0.2](../../../design/workflow_mbse_architecture.md)。输入为同次选择的产品、生命周期退役决定、退役计划、依赖和保留要求、归档与知识转移材料；执行后补入真实处置证据与退役包检查。

配置的人或 AI AGENT 判断计划是否足以授权所请求动作；实际执行后的材料按选定规则评价，用于退役包合规与外层关闭。两者不能互相替代，本规范不增设退役后关卡或全局人工审批。通用要求见[模型与追溯语义约束](../model_traceability/semantic_constrains.md)、[运行语义约束](../workflow_execution/semantic_constrains.md)与[目录总说明](../README.md)。

## 允许工作与产出

允许评价退役范围、运行依赖处置、数据与资源保留、停用顺序、故障恢复和交接充分性，作出限定授权或要求补充准备；执行后评价实际结果、归档可用性与遗留责任。产出为引用具体材料和证据的新判断、条件及未决项，写开发区或原 release 外部；结构遵循[本阶段语法约束](syntactic_constrains.md)。已发布对象和必要依赖始终保持，退役成果若发布由[发布评审](../project_release/semantic_constrains.md)支持创建独立新对象。不能用未来计划替代已完成事实，也不能以授权结论推定执行成功。

## 规则

| ID | 约束判定 | 诊断位置或评审证据 |
| --- | --- | --- |
| RET-SEM-001 | AGENT 判断退役产品、范围与生命周期处置决定一致，退役依据仍适用于当前产品和观察；剩余 wish 义务、用户影响与替代安排已被识别。只有“项目结束”字样不足以支持产品退役范围。 | 产品/观察选择、生命周期理由、wish 义务与受影响主体。 |
| RET-SEM-002 | 退役计划应覆盖关键外部依赖、共享部件、运行接口和资源；AGENT 判断停止或处置这些对象是否会损害范围外服务。共享身份存在时，不能因为一个 wish 退役而默认删除共有设计或证据。 | 依赖模型、共享资源清单、范围分析和替代安排。 |
| RET-SEM-003 | 行动顺序、前提、责任、失败处置及可恢复边界应足以执行所请求退役；AGENT 区分可撤回步骤和效果不可确认的步骤，判断何时应停止或核对事实，不能把重复命令当作必然安全恢复。 | 停用方案、风险与恢复分析、预演或相关事实证据。 |
| RET-SEM-004 | 数据、配置、记录和运行资源的保留或销毁选择应符合选定策略与责任，且不能删除或改变已发布对象所需依赖；AGENT 评价保留不足、过度保留与无人承担的缺口。真实策略和处置记录保存在原 release 外，不通过修改旧清单追认处置。 | 外部策略/处置记录、对象映射、发布依赖和责任依据。 |
| RET-SEM-005 | 归档应保留足以重建产品、wish 追溯、实际证据、规则选择与决定历史的内容；AGENT 判断引用及依赖在停止服务后是否仍能读取，外部易失链接需有明确保留安排。 | 归档索引、版本摘要、实际读取验证和外部资源保留。 |
| RET-SEM-006 | 知识转移与剩余支持责任应覆盖需继续理解、读取或处置的对象，接收职责和材料适用性可解释；模板签名或 AI 生成的交接文本不能证明真实接收、培训或理解已发生。 | 知识材料、接收角色、真实转移观察和未决责任。 |
| RET-SEM-007 | `Retirement authorization` 应只授权选定产品与计划中的具体工作，并说明为何准备充分、哪些条件仍需执行；AGENT 不预先把停用结果、实际归档或后置检查评价为已成功。 | 授权范围、前置准备证据、理由与执行条件。 |
| RET-SEM-008 | 退役后证据应足以支持已声明的停用、处置、保留和归档主张；AGENT 或配置评审职责评价部分完成与结果不确定的边界。命令成功、某一资源消失或状态为 archived 不证明全部退役义务履行。 | 实际效果、资源核对、失败/未执行项与后置检查。 |
| RET-SEM-009 | 关闭结论应说明仍存的责任、保留限制和恢复/查询入口，并明确源模型 `closureAuthorized` 与 `recordValid` 的真实依据；退役关闭、运行停止和历史 wish 完成分别解释，不能追溯改写已有完成事实。 | 关闭材料、有效授权、退役包证据与历史完成选择。 |
| RET-SEM-010 | 用户修改授权或关闭结果时，例外需有明确规则、对象、理由及影响边界，原失败、未执行检查与已发生效果保留；后续动作根据有效决定及实际前提判断，不能将未知处置结果或缺失归档伪造成已满足。 | 用户新决定、例外范围、原始事实、依赖影响和调度前提。 |
| RET-SEM-011 | AGENT 判断退役所采用的固定 T1、用户约束版本和保留策略是否明确，并说明新策略对本次动作的影响；规则显式换版不改工具机制、旧发布或旧检查事实。旧证据各自依据的输入和规则应足以解释本次退役判断，不重标为新检查。 | 工具绑定、策略差异、采用范围、旧证据依赖与理由。 |
| RET-SEM-012 | 退役后仍须能够独立读取相关发布及其完整必要依赖；AGENT 判断共享不可变对象保留、外部撤回说明和知识入口是否充分。无需复制无关全部历史，但不能以归档、撤回或替代为理由修改旧 release、删除被引用对象或用缓存覆盖包内渲染。 | 发布依赖充分性、读取核对、外部说明与缓存写入边界。 |

## 出口与返工

前置通过结论应解释授权范围与条件，有效 `Retirement authorization` 和输入生命周期决定满足源模型前提后才执行 `decommissionAndArchive`。执行后依据实际材料与证据评价退役包；外层仅在 `closureAuthorized` 与 `recordValid` 同时满足时走 `lifecycleClosed`。规划充分、授权有效和执行完成分别保存。

准备不足则补充计划或改变退役范围后重新选定材料并判断；执行失败或效果不确定则保留事实、核对已发生效果并明确后续尝试与授权。源模型没有自动补做或自动批准分支，不在文档中把缺口包装为新关卡。涉及上游缺陷时按影响分析回到受影响阶段，保留实际退役和归档历史；用户例外只影响明确范围，实际调度前提继续如实评价。

## 示例

合格：AGENT 对产品、依赖和保留方案作前置评价，仅授权所列停用及归档动作；实际执行后逐项核对效果，未完成的共享资源处置保留责任边界，归档可重建且关闭条件有真实证据支持。

不合格：因为计划完整就提前宣布退役完成，清理一个 wish 时删除共享组件和其他 wish 的证据，又以“停止运行”代替保留、归档和知识转移的检查。
