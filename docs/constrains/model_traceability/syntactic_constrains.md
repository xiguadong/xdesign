# 原生模型、追溯与 view：语法校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围与依据

适用于工具公共定义、用户约束模型、项目模型、每条 Wish 的独立模型及共享设计。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)“开发区的三类模型”“目标目录与读写归属”；执行方式遵循[目录公共协议](../README.md)。这些规则描述结构合规要求，检查器实现与实际执行结果另行记录。

输入为本次源文件集合、项目绑定工具及固定依赖、选定用户约束、原生元素到应用身份的绑定、产物清单及当前阶段契约。允许新增或更新开发区本阶段负责的模型、关系和 view；工具机制和旧发布对象只读。输出为可恢复的原生源文件、解析诊断、身份和引用检查结果。必要关系按阶段渐进建立。

## 规则

| ID | 约束与判定方法 | 诊断位置 |
| --- | --- | --- |
| MT-SYN-001 | 使用选定 SysML 工具与库解析实际源文本；语法错误、库加载失败、名称歧义、类型或原生关系合法性错误分别报告。语言 profile 不支持的表达给出诊断，不能静默忽略。 | 源文件、行列、限定名、工具诊断 |
| MT-SYN-002 | 每个命名空间、元素及产物有可定位身份；应用稳定身份与原生元素显式绑定。身份重复、重命名后绑定丢失、同一身份指向两个可修改来源均报告失败。限定名变化不得隐式新建业务身份。 | 身份绑定与来源清单 |
| MT-SYN-003 | 共享定义保持一个维护来源，Wish 选择明确版本并通过原生 import 引用命名空间。加载集合出现重复 `VModelAgents` 定义需报告冲突；源文件集合选择不能以文件路径伪装原生 import。 | 定义源、import、加载清单 |
| MT-SYN-004 | 每条纳入范围的 Wish 有独立源模型、命名空间、原始提交引用和独立 view。多个 Wish 共享的项目元素通过相同稳定身份引用，不在各链中复制成独立维护元素。 | Wish 模型、原始提交绑定、共享引用 |
| MT-SYN-005 | 项目组成用 part、port、interface、action 等适用原生元素及真实组成/行为关系表示；仅列出文件、Wish 或产物不能满足项目组成的必需结构。 | 项目模型与阶段必需元素清单 |
| MT-SYN-006 | 关系有类型、源端、目标端、方向及适用版本；细化、满足、实现、计划验证、实际执行、证据支持、完成判断分别可识别。可适用的满足/验证使用原生 satisfy/verify；自定义 dependency 角色有领域定义，不能凭显示标签推断标准关系。 | 关系定义、端点及版本 |
| MT-SYN-007 | 本阶段要求的追溯端点全部可解析；下游尚未发生的执行或完成记录标为未产生。引用存在性、类型和基数检查不能把计划、定义或预期产物当成实际产物。 | 阶段契约、关系端点、产物记录 |
| MT-SYN-008 | 每个项目维护的 `.sysml` 文件有归属明确的 view usage，默认同文件；拆分时保留归属绑定。检查 view 选择语法、暴露元素和关系引用，通用 view definition 不能代替具体模型的 view usage。 | 模型文件、view usage、归属记录 |
| MT-SYN-009 | view 的被选元素及关系有可恢复来源；显式暴露共享关系时端点可以定位。渲染输入记录模型、view 和运行选择；HTML、图片或 `%viz` 输出不能代替原生 view 声明。 | view 选择、渲染输入清单 |
| MT-SYN-010 | 模型中的实际检查、证据和决定为类型化引用节点，解析到 ProjectStore/受管理资源中的原记录；记录事实只有一个维护来源。复制日志摘要允许作为展示，不得形成第二份可独立修改的事实。 | 记录引用、类型绑定、存储来源 |
| MT-SYN-011 | 外部资料定位到身份、选定版本和章节标识，附关联模型元素及理由。章节失效或历史内容不可恢复报告缺失，不自动改指新版同名章节。 | 外部引用及章节定位 |
| MT-SYN-012 | 基线固定源文件、库、工具、规则、外部材料及关系选择，能够通过可达提交或快照恢复；保存采用版本检查，冲突保留原内容。可恢复候选、未完成编辑和尝试输入不得只存可丢弃缓存。 | 基线清单、保存结果、内容摘要 |
| MT-SYN-013 | 加载、编译、关系解释、渲染和查询使用项目初始化绑定的同一工具发布及固定依赖；用户约束 SysML 依赖其公共元模型/扩展接口，不改动固定 V-model 和机制。 | 工具绑定、加载与规则模型 |
| MT-SYN-014 | 保存只写开发模型/约束与新记录，打开发布使用其固定工具和冻结模型/view；原位保存旧发布必须拒绝，内容摘要异常报告损坏，重新渲染不覆盖包内文件。 | 区域归属、只读路径、发布读取诊断 |

## 出口与缺口处理

逐条输出公共协议定义的结果与诊断。解析和引用可用是后续检查的前提；缺失或冲突不能被“图看起来正确”覆盖。语言与结构通过后仍需[工程语义评审](semantic_constrains.md)；设有关卡时按[运行规则](../workflow_execution/syntactic_constrains.md)提交该关卡，无关卡动作保存实际事实与条件判断，按固定流程推进。变更按引用依赖定位受影响阶段，不清除旧模型或记录。

## 判定示例

合格结构：`W001.sysml` 与 `W002.sysml` 分别有自己的 Wish 命名空间和 view，均引用项目中稳定身份为 `coordinator` 的同一部件；两条链各自绑定本次阶段产物与选定版本。

不合格结构：两条链各复制一份同名协调器；或同一加载集合同时包含根目录两份 `VModelAgents` 定义；或只有一张关系图片却没有原生 view usage。即使单文件解析成功，也不能据此判定整个选择结构合规。
