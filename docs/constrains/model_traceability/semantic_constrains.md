# 原生模型、追溯与 view：语义校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围与评审依据

适用于所有阶段对用户约束、项目模型、Wish 链和原生 view 的工程判断。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)，使用[公共评审协议](../README.md)。输入为同一材料选择上的源模型、实际阶段产物、语法诊断、原始 Wish、关系定义及已发生的记录；由该 workflow 配置的 AGENT 评审。此文档不代表评审已执行。

允许评估、提出模型修正及受影响范围；输出为逐项理由、证据、缺口和关卡建议。审查当前阶段应当成立的主张，不要求在需求阶段提交尚未产生的实现证据。

## 规则

| ID | 工程判据 | 必须检查的材料或说明 |
| --- | --- | --- |
| MT-SEM-001 | 原生模型表达实际被开发系统的组成、接口、行为及责任；粒度足以解释当前阶段问题，不以目录清单替代系统设计。 | 项目组成与行为、阶段任务、关键职责 |
| MT-SEM-002 | 每条 Wish 的意图解释忠实于原始来源，覆盖其当前范围；共享增量不能用另一条 Wish 的通过结论代替本条判断。 | 原提交、Wish 模型、范围与增量选择 |
| MT-SEM-003 | 每个追溯关系表达可说明的工程主张。AGENT 说明为何该需求细化意图、设计满足需求、实现落实设计、证据支持结论；存在连线只证明声明存在。 | 关系理由、源目标内容及适用证据 |
| MT-SEM-004 | 关系方向和类型符合其工程含义。执行 succession 不充当满足关系，verify 计划不充当实际测试成功，自定义 dependency 的含义不超出其定义。 | 原生关系、领域角色定义、实际执行引用 |
| MT-SEM-005 | 独立 Wish 链足以说明该意图对共享系统的具体影响，保留各自需求与完成范围；共享元素保持整体一致，没有因局部修改引入冲突责任或接口。 | 多 Wish 影响、共同部件及其需求 |
| MT-SEM-006 | view 能展示本阶段审查需要的元素、关系、未完成项及关键共享上下文；选择没有隐藏影响判断的失败、断链或冲突。 | 原生 view 选择与完整模型对照 |
| MT-SEM-007 | 展示层准确区分定义、具体 usage、当前产物、实际运行和历史版本。导入库或默认布尔值不会被显示成已执行实例与成功事实。 | 渲染输入、来源类型、运行记录 |
| MT-SEM-008 | 证据和决定适用于被审工程主张的具体版本、环境和范围；跨版本复用有影响分析与明确适用依据，不能自动继承旧结果。 | 证据版本、选择差异、适用性说明 |
| MT-SEM-009 | 外部资料的选定章节与主张相关且充分；引用理由解释章节支持了什么，摘要没有扩展成原文未表达的要求或结论。 | 可恢复章节、引用理由、模型主张 |
| MT-SEM-010 | 信息归属保持可解释：Git 保存工程内容，ProjectStore 保存运行事实，受管理资源保存证据，缓存可重建。候选到采纳的转换有依据和结果，不以保存成功代替批准。 | 来源、采纳记录、审查决定 |
| MT-SEM-011 | 相关变更的影响按选定依赖传播，覆盖已受影响关系和关卡；无关 Wish 范围不被无理由撤销。影响分析解释重新评审与保留决定的理由。 | 差异、依赖图、受影响范围 |
| MT-SEM-012 | 工具自举使用固定工具或明确引导机制，候选工具代码/V-model 不替换当前执行机制；完成验证后发布 T2 供新项目使用。用户规则成果显式采纳，业务 Wish 成功不代替工具控制能力验证。 | 引导机制、工具/规则发布历史、两类验证计划 |
| MT-SEM-013 | 工具追溯/渲染机制与可变追溯内容/view 清楚区分；规则和项目资产能持续增长，开发修改与用户新决定只影响开发选择，不改变旧发布内容或关系。 | 机制/内容归属、保存边界、R1/R2 对照 |
| MT-SEM-014 | 发布选择包含成果与所需证据的完整依赖，保留证据原输入和规则；不复制全部历史而仍可独立读取重建。共享内容以不可变身份复用，不能把可变路径当冻结引用。 | 发布依赖闭包、证据适用性、保留与读取依据 |

## 出口与返工

AGENT 记录每条适用规则的支持与不足；设有关卡时形成相应有效决定，无关卡动作保存事实和条件判断，按固定流程推进。图完整而关系缺乏工程依据时建议返工到建立该主张的阶段；证据不可确认时记录不确定，不把结构通过当作充分性结论。用户替代决定及例外按[公共协议](../README.md)保存，原主张的支持状态继续保留。

## 判定示例

支持充分：系统验证结果引用协调器实现版本及需求 `R12`，实际暂停恢复观察解释了如何满足该需求；Wish view 展示需求、实现、观察和当前决定。

支持不足：模型中画出 `R12 → verify` 后直接声明 Wish 完成，只有计划定义而没有暂停恢复的实际观察；或 view 为显示“全通过”而省略同一版本的失败结果。
