# 集成与接口验证阶段的语义约束

规则集版本：0.1。日期：2026-10-12。状态：目标约束。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围及依据

本规则用于判断集成结果是否充分支持选定架构及接口的符合性，对应 `Integration review`；下一工作是系统验证。判断由 workflow 配置的人或 AI AGENT 承担，记录理由、范围与不确定性。机械结构通过或模型有连接关系均不等于真实集成成功；规则描述目标要求，不宣称已有检查器实现。

依据：[整体架构设计](../../../design/workflow_mbse_architecture.md)（0.2）的“用户约束如何演进”“两个区域的操作边界”“最小可执行范围”，[V-model 定义](../../../v_model_agents.sysml)的 `IntegrationAgentBehavior` 与 `integrationVerifiesArchitecture`，以及 [Wish 生命周期模型](../../../wish_to_product.sysml)的 `IntegrationSpec`、`IntegrationBundle` 和相关上游 flow。

通用要求见[路由说明](../README.md)、[模型与追溯语义约束](../model_traceability/semantic_constrains.md)、[工作流执行语义约束](../workflow_execution/semantic_constrains.md)；机械结构要求见[本阶段语法约束](syntactic_constrains.md)。

## 输入、允许工作与产出

评审和用户替代决定形成新的开发记录；不回写旧发布。纳入后续发布的早期证据保留其真正检查输入、上游模型、实现和规则版本，AGENT 评价它对当前选择的适用性，不能重标为针对最终内容重新执行。相关要求见[项目发布语义约束](../project_release/semantic_constrains.md)。

评审使用选定架构与接口、已验证组件及其限制、实际集成配置、计划/程序、原始执行与接口观测、环境、覆盖、异常及处置、检查结果和变更影响。顺序输入来自组件验证，被验证依据来自架构阶段。

允许判断架构及接口符合性、分析相互作用与异常、要求真实联调、追加故障场景、提出配置/组件/架构返工。产出为语义评价、系统验证的已知前提和 `Integration review` 决定；不能通过评审推定未进行的联调已成功。

## 规则表

| ID | 约束判定 | 评审证据 |
| --- | --- | --- |
| IV-SEM-001 | 实际参与集成的组件、服务、部署和依赖组合应代表当前选定架构；组件验证的限制和已知问题纳入评价。不同版本或替代件的组合只能支持经过论证的范围。 | 集成清单、组件验证决定及限制、架构基线、配置差异。 |
| IV-SEM-002 | 架构及接口符合性需要实际联接、交互、分析或演示的观察支持。模型端口连接、接口文档一致、各组件单独通过或集成计划存在不足以证明真实组合行为。 | 实际消息/调用日志、联调观察、分析方法、组件间因果链。 |
| IV-SEM-003 | 验证应覆盖接口的工程含义，包括选定规格要求的数据/单位、方向、协议、状态、时序、错误与恢复；仅“能连接”或收到任意响应不足以支持接口完整符合。 | 接口规格与逐项判据、编码/单位检查、时序与错误路径结果。 |
| IV-SEM-004 | 相互作用应支持架构分配的责任、数据流、控制流和资源约束。识别顺序依赖、竞争、死锁、故障传播等相关风险，不能把局部接口通过直接推广为整体组合行为正确。 | 架构行为、责任分配、跨组件场景、资源/并发与故障证据。 |
| IV-SEM-005 | 覆盖包含当前范围的关键接口、组件组合、顺序、边界和异常交互；按风险说明未集成、未验证或只能模拟的部分。接口数量覆盖率不能取代关键交互及场景覆盖。 | 集成计划覆盖、接口/场景矩阵、未覆盖项、风险排序。 |
| IV-SEM-006 | 环境、网络/总线条件、部署、真实依赖及测量方法应足以支持结论。模拟响应、理想网络或缩减负载的局限应说明，不能把该结论无条件推广到实际运行组合。 | 环境对照、替代件差异、网络/负载条件、测量精度及限制。 |
| IV-SEM-007 | 通过结论基于实际观察满足选定架构/接口判据。无响应、中断、未知外部效果或偶发失败须解释和处理，不能归为成功；不适用接口须有架构范围依据。 | 逐项实际与预期结果、未知项核对、波动/偶发故障分析、排除依据。 |
| IV-SEM-008 | 异常处置应解释根因及影响，并以相关复验和回归支持问题闭环。重启后通过、单独组件通过或删除失败日志，不足以证明跨组件故障已解决。 | 原始异常、根因定位、修订、复验及相邻接口回归结果。 |
| IV-SEM-009 | 变更评估应识别组件、接口、架构、配置与环境变化引起的集成证据失效，保留原执行输入/规则以及复用的依据和限制，不将旧证据重标为最终内容执行；影响到组件内部行为或架构职责时选择相应更早返工阶段。 | 差异与依赖追溯、失效范围、复用理由、复验/返工选择。 |
| IV-SEM-010 | 未解决问题、残余风险和限制必须足以让系统验证判断其输入是否可用。阻塞性架构/接口不符合不得被结构通过掩盖；有效例外决定应说明授权、范围、限制和后续处置。 | 问题分级、残余风险、系统验证输入前提、例外决定及历史。 |
| IV-SEM-011 | `Integration review` 明确判断选定架构与接口范围，决定理由和证据一致，并说明能否进入 `systemVerification`。集成通过不能替代系统需求验证、使用确认或 wish 完成；用户修改决定新增开发记录，不改变原始观察的含义或旧发布内的决定。 | 语义评价、决定及审查包、后续工作范围、用户替代决定记录。 |
| IV-SEM-012 | 对发布相关架构与接口，实际跨模块证据应证明固定 T1 正确传递，候选选择不跟随开发编辑，保存与用户改决定只影响开发区，封存失败不产生成功发布。R1 后修改约束/模型/文档/决定再发布 R2 时，评价 R1 内容、决定、依赖未变且可用原 T1 读取/展示；结论限定架构及接口范围，不替代系统需求和验收判断。 | 跨模块调用/事件、候选标识、失败注入结果、R1/R2 对照及原 T1 读取。 |

## 出口与返工

AGENT 对同一材料选择记录待判断、通过、返工或拒绝。通过意见提交为可归属的关卡决定；协调器结合当前有效决定、契约与运行前提允许系统验证。残余风险被允许时，明确本次许可的范围及需要后续证明的事项。

接口证据不足时补充集成验证；组件问题返回组件验证/实现；职责、接口或组合设计错误按影响返回架构等上游阶段。未知外部效果先核对再安排重试。返工保留原证据、失败与决定，用户修改决定生成新的有效记录。

## 例子

合格：两个真实组件在选定网络条件下完成正常交换、单位检查、乱序消息和断连恢复。首次恢复失败保留日志并定位为接口状态不一致，修订后复验及相邻接口回归通过。AGENT 说明高负载上限仍需系统验证确认，并依据架构分配及接口范围允许进入系统验证。

不合格：两端各自通过单测，使用总能返回成功的桩跑通一次调用，据此宣称真实网络集成和所有故障恢复符合架构。缺少真实交互、异常覆盖及替代件适用性，违反 IV-SEM-002、003、005、006，即使配置表和关系结构齐全也不足以放行。
