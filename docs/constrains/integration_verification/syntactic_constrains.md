# 集成与接口验证阶段的语法与结构约束

规则集版本：0.1。日期：2026-10-12。状态：目标约束。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围及依据

本规则用于 `integrationVerification` 阶段的实际集成配置、接口验证、执行记录和审查包；关卡为 `Integration review`，后续工作为 `systemVerification`。语法层涵盖语言引用及类型、记录结构、版本与关系等可机械判定内容，不宣称检查器已经实现；检查通过不等于集成关卡通过。

依据：[整体架构设计](../../../design/workflow_mbse_architecture.md)（0.2）的“固定工具与项目环境”“两个区域的操作边界”“一次发布的执行过程”，[V-model 定义](../../../v_model_agents.sysml)的 `IntegrationAgentBehavior`、`integrationVerifiesArchitecture` 和 `Integration review`，以及 [Wish 生命周期模型](../../../wish_to_product.sysml)的 `IntegrationSpec`、`IntegrationBundle`、`ProducedBundle` 和 `ContractedVModelDevelopment::integrationVerification`。

通用要求见[路由说明](../README.md)、[模型与追溯语法约束](../model_traceability/syntactic_constrains.md)、[工作流执行语法约束](../workflow_execution/syntactic_constrains.md)；工程判断见[本阶段语义约束](semantic_constrains.md)。

## 输入、允许工作与产出

本阶段的模型、材料、实际证据、检查及新决定写入开发区持久资产/记录；从已发布成果继承时只读选定内容。用户修改结果新增开发决定，旧发布内的内容、原规则选择、决定及证据不变。提交发布时再按[项目发布语法约束](../project_release/syntactic_constrains.md)选择依赖并创建新的不可变发布，本阶段关卡不替代发布操作。

输入包含选定 wish/增量与尝试、当前组件验证基线及实际组件构建、架构与接口基线、集成计划/程序，以及流程、定义库和规则版本。组件验证基线是顺序输入；架构与接口基线是被验证依据，都要纳入依赖清单。

允许按选定计划装配/连接组件、执行集成与接口验证、登记真实配置和观察、更新集成模型与 wish view、报告异常和影响。需要修改组件、架构或接口时，按变更影响形成受控返工和新尝试。

产出包含集成配置模型、接口及验证用例、配置清单、实际程序/结果和原始接口日志、覆盖及缺口、异常处置报告、版本清单、结构检查结果与 `Integration review` 审查包。现有模型未定义的运行状态、环境、观测和历史字段，保存在契约选定的结构化附属记录或明确类型的模型扩展中。

## 出口与返工

缺项和结构错误返回可定位诊断。满足结构要求的材料交给 workflow 配置的人或 AI AGENT 判断架构及接口符合性；协调器依据当前有效 `Integration review` 决定、产物契约和输入适用性安排系统验证。

失败或不确定结果按实际状态保留。返工由影响评估选择集成、组件验证、实现、架构或其他流程声明的位置；不能仅靠重新排列结果、重置状态或重复执行覆盖失败历史。

## 例子

合格：集成配置 `INT-9` 列出两个组件构建与真实协议端点，用例 `IF-3@2` 关联接口 `IF-TEMP@4`。首次握手失败保存消息日志及 `ANOM-12`；修订配置后的新运行引用首次记录，复验通过。覆盖表列出未执行的冗余链路用例，审查包包含该缺口，结构检查不会将其计算为通过。

不合格：模型连接了两个端口，就登记“接口验证完成”；实际一个端点是模拟器却写为真实组件，没有执行时间、网络配置和消息日志，超时结果计入成功。违反 IV-SYN-003、005、006、007。
