# 运行观察与生命周期演进的语义充分性约束

规则集版本：0.1。日期：2026-10-12。状态：目标规范；此处的判断职责不表示已接入运行系统、AI 或实际评审服务。

## 适用范围、依据与输入

适用于 `OperateAndObserve` 的观察充分性、`DecideLifecycle` 的 `Lifecycle disposition` 判断和 `PrepareNextIncrement` 的变更准备。依据[生命周期源模型](../../../wish_to_product.sysml)、[V-model 的 ReviewAgent 与 ChangeControl](../../../v_model_agents.sysml)及[整体架构设计 0.2](../../../design/workflow_mbse_architecture.md)。输入是选定已发布产品、真实观察包、wish 完成和使用范围、运行/维护约束、候选生命周期选择与新版本影响材料。

配置的人或 AI AGENT 根据证据决定继续运行、演进、退役或保持待处理，说明理由、反例、遗漏与不确定性。遥测数量、运行时长、成功退出和语言检查只提供事实，不能替代 `Lifecycle disposition`。普通观察与准备动作不在本规范中新增关卡。通用要求见[模型与追溯语义约束](../model_traceability/semantic_constrains.md)、[运行语义约束](../workflow_execution/semantic_constrains.md)及[目录总说明](../README.md)。

## 允许工作与产出

允许评价观察覆盖、问题影响、维护结果和产品持续适用性，对候选选择进行比较，准备新 wish 版本与影响边界。输出为有证据和范围的生命周期理由、当前授权决定、未决项及新增量准备结论，保存到开发区；结构遵循[本阶段语法约束](syntactic_constrains.md)。运行目标或需求发生变化时，保留来源并提出明确变更，不能仅修改运行结论消除工程缺口。已有 R1 始终只读，成果变化经开发及[发布评审](../project_release/semantic_constrains.md)形成独立 R2。

## 规则

| ID | 约束判定 | 诊断位置或评审证据 |
| --- | --- | --- |
| LC-SEM-001 | AGENT 判断观察是否能反映实际产品在声明范围内的行为，包括关键用户、环境、负荷与异常；对数据空白、采集失效和使用偏差说明限制。没有收到事故报告不能推导出没有问题。 | 观察计划、数据覆盖、采集健康与遗漏分析。 |
| LC-SEM-002 | 遥测、用户反馈、事件和维护结果应足以评价原 wish 的预期成果及现有验收条件是否仍成立；AGENT 比较技术指标与用户成果，识别需求符合但用途偏离的情况。 | wish 到运行指标映射、原确认范围和实际反馈。 |
| LC-SEM-003 | 事件处置应识别根因及可能受影响的需求、架构、设计、实现和证据；临时恢复并不自动解决工程问题。AGENT 判断是否需要受影响阶段新尝试，并解释无需返工的依据。 | 事件观察、根因分析、追溯影响与返工范围。 |
| LC-SEM-004 | `continueOperations` 应有当前运行与维护可接受的证据、限制和再次观察条件；AGENT 评价已知问题与趋势对后续使用的影响。现有发布或既往验收不能无条件批准永久继续运行。 | 当前观察、风险趋势、使用限制与复评触发条件。 |
| LC-SEM-005 | `evolve` 应有可追溯的变更需求、预期收益与影响边界，并解释继续运行、维护、暂停等候选为何不足；AGENT 判断变更是否仍属于原 wish 的新版本，避免用身份不变掩盖完全不同的意图。 | 变更来源、候选比较、wish 新版本及范围理由。 |
| LC-SEM-006 | 新增量应保留已发布历史，同时足以重新评价受影响路径；AGENT 判断旧证据复用、未变部分和失效决定的边界。已过关卡不能因为文本相似或代码差异小而自动继承。 | 依赖影响、旧证据适用性、失效清单及新增量计划。 |
| LC-SEM-007 | `retire` 的推荐应解释停止使用的依据、受影响主体、替代服务或剩余责任，且说明退役准备尚需完成。生命周期处置授权不能代替后续 `Retirement authorization` 和实际退役证据。 | 候选比较、退役触发依据、责任与退役准备入口。 |
| LC-SEM-008 | `hold` 或证据不足时应明确不确定性、补充材料或纠正条件、允许的有限行为及恢复所需判断；有效停止结果应有可归属依据。AGENT 不能通过等待时间或默认值制造自动恢复批准。 | 待处理理由、补充条件、运行限制与恢复决定。 |
| LC-SEM-009 | 生命周期决定只覆盖选定产品、观察区间和下一项工作；AGENT 判断所选范围与授权一致，明确后续变化的重新评价条件。历史 wish 完成与当前运行适用性分别表达，发现新问题保留并传播影响。 | 关卡范围、授权选择、当前适用性与完成历史。 |
| LC-SEM-010 | 用户修改生命周期结果的例外应具有明确范围、理由及影响评价，原失败、未执行观察和旧判断持续可读；AGENT 或协调器按选定流程/profile 评价可继续性，不能据新结论推定数据、授权或调度能力已自动补齐。 | 用户新决定、例外边界、历史证据、影响与实际调度前提。 |
| LC-SEM-011 | AGENT 判断演进是否明确区分固定 T1 与可变工程资产/约束；新约束只在显式选择后用于新的判断，不重标旧观察和证据，也不改变既有 V-model 关卡与机制。若变更要求新工具能力，应作为单独迁移设计而非普通新增量默认升级。 | 工具绑定、变更分类、约束采用范围与迁移候选说明。 |
| LC-SEM-012 | AGENT 判断从 R1 只读继承到开发、再封存 R2 的边界是否可解释，R1 所需依赖仍保留且独立可读。当前事件、用户替代决定、撤回说明和缓存不改 R1；R2 只采纳相关充分依据，不以复制全部历史或覆盖旧发布替代依赖分析。 | 继承边界、R1/R2 依赖、开发决定、外部说明与发布核对。 |

## 出口与返工

语义结论说明选定 choice、其适用范围、理由和所需条件；源模型的授权、`decisionCurrent` 与实际调度前提共同控制下一项工作。choice 与工作按 `continueOperations → operate`、`evolve → evolve`、`retire → retire`、`hold → holdForAuthority` 配对；有效停止条件进入 `stopLifecycle`。处于 hold 时，没有自动批准或自动恢复。

新增量准备充分才返回 `clarify`，继而进入可行性及 V-model。观察发现需求、设计、实现或验收问题时，建立影响分析和新尝试，重评受影响决定；不改变旧观察与旧发布事实。源模型未规定的修复调度需由选定流程/profile 明确表达，不能在普通运行步骤中跳过关卡。

## 示例

合格：AGENT 发现产品技术指标合格但目标用户成果持续下降，结合反馈和变化后的使用条件选择演进；明确新 wish 版本、受影响需求与确认路径，旧运行证据仅在不变范围内有理由复用。

不合格：运行日志没有报错便认定继续运行安全，忽略遥测采集已停；后来决定演进，却把原验收和所有完成结论直接继承到新产品，既不分析影响也不重新选择证据。
