# Wish 登记、初始化与澄清：语法校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围、输入与产出

覆盖 `WishToProductLifecycle` 中 `IntakeWish`、`InitializeIncrement`、`ClarifyWish`，依据[生命周期模型](../../../wish_to_product.sysml)和[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。沿用[公共协议](../README.md)、[模型](../model_traceability/syntactic_constrains.md)与[运行](../workflow_execution/syntactic_constrains.md)规则。这些规则是目标要求。

输入为用户原始提交、来源/提交者信息、项目绑定的工具 T1 及依赖（首次项目初始化时建立），项目及引导基线。允许登记、建立独立 Wish 模型及 view、初始化增量、澄清用途/限制/验收意图；不替用户虚构认可或关卡批准。输出为原始来源引用、稳定 Wish 身份、工程解释、工作上下文、澄清记录与待解决问题，均写入开发区持久资产/记录。增量初始化核对并继承项目工具绑定，不给每条 Wish 重新选择工具内核。

## 规则

| ID | 约束与判定方法 | 诊断位置 |
| --- | --- | --- |
| WI-SYN-001 | 原始提交有身份、来源、提交内容及版本/时间定位，在开发区持久记录中保留原内容（可由 ProjectStore 保存）；工程解释引用原提交，不以整理后的文本覆盖用户当时表达。 | 原始 Wish 记录及引用 |
| WI-SYN-002 | 登记结果能定位 Wish 身份、所有者/来源、陈述、版本和项目范围，空身份或身份冲突报告缺失/冲突。 | `Wish`、登记清单 |
| WI-SYN-003 | 每条 Wish 有独立原生源模型、命名空间、原始提交绑定和 view，引用项目固定 T1 提供的公共定义库与当前项目元素；实际源文本使用原 T1 检查可解析。 | Wish 模型、绑定、诊断 |
| WI-SYN-004 | 工作上下文有增量身份、输入基线和大于零的迭代号；基线内容可恢复，初始/先前发布选择可区分。模型 `contextPrepared` 由真实记录支持；上下文关联项目 T1 绑定、初始用户约束选择及继承发布（如有），这些扩展信息可通过类型化附属清单表达，不假定现有 `WorkContext` 已有相关字段。 | `WorkContext`、基线清单 |
| WI-SYN-005 | 澄清记录包含使用者、使用情境、预期结果、限制、假设和验收意图，分别注明已知与待澄清内容及其来源。 | 澄清材料和章节 |
| WI-SYN-006 | 提问、回答和工程解释有来源/版本关联，未确认假设明确标注；不能仅把 `sufficientlyClear=true` 写入模型作为澄清执行记录。 | 澄清来源、状态和观察 |
| WI-SYN-007 | 重复请求或 Wish 修订保持原身份及历史，新范围/新提交关系明确；共享材料以稳定引用接入，不复制共享项目设计。 | 登记去重、修订与引用 |
| WI-SYN-008 | 新增澄清文档按公共规范命名、注明身份与版本，原生模型与资料/问题能定位；外部资料引用具体内容和章节。 | 文件、章节、问题记录 |
| WI-SYN-009 | 按源模型执行 `intake → initialize → clarify`；上下文不足或澄清未充分进入 `holdForAuthority`，不得凭默认值继续。登记/澄清不虚构新关卡。 | action 顺序、条件与状态 |
| WI-SYN-010 | 澄清充分且上下文准备后，将选定 Wish 和上下文传给 `feasibility`；暂停恢复附新的有效上下文/依据，保留先前记录。 | 交接、暂停恢复记录 |
| WI-SYN-011 | 首次项目初始化建立可恢复的工具绑定，如 `.xflow/tool.lock` 或等价清单，固定 T1、V-model、公共元模型、编译/解析、渲染、追溯及工具依赖版本/摘要和读取位置；新增 Wish/增量验证一致性，不因本机更新重绑。既有项目工具升级进入独立迁移设计。 | 项目工具绑定、初始化日志、工具库与依赖清单。 |
| WI-SYN-012 | 初始及修订用户约束 SysML、文档规则明确版本与采用范围，新尝试显式选择；继承 R1 记录只读来源和新开发位置，后续形成 R2 时仍保留 R1 的原内容与工具选择。澄清修订不覆盖旧发布内容，早期来源/判断保留原选择，发布操作另按[项目发布语法规则](../project_release/syntactic_constrains.md)。 | 约束清单、继承/开发目标、修订与历史引用。 |

## 出口与返工

语法结果和[语义判断](semantic_constrains.md)分别保存。此入口没有额外设定的审批关卡；按源流程的准备/澄清条件进入可行性评估。缺失来源、上下文或用途依据时等待补齐，在登记或澄清建立新记录，不自动启动开发。

## 判定示例

合格结构：登记 `W001`，保留原始文字，建立独立模型与 view；输入基线可恢复，澄清材料标明哪些验收意图来自用户，哪些仍是待确认假设。

不合格结构：只有 AI 改写后的需求，没有原提交；或上下文身份为空却将 `contextPrepared` 和 `sufficientlyClear` 默认填为真。
