# Wish 登记、初始化与澄清：语义校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围与评审依据

适用于开发前 Wish 解释与澄清充分性的判断，依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)及[生命周期](../../../wish_to_product.sysml)，遵循[公共规范](../README.md)。输入为原提交、Wish 模型、澄清材料与来源、工作上下文及结构结果；由所配置主体作出明确的工程判断，保存依据。此目标不新增源模型未定义的关卡。

允许解释意图、披露假设、提出澄清及范围划分；输出为是否足以进入可行性评估的理由与缺口，保存为开发记录。已发布来源只读继承，修改意图/模型/文档与判断不回写旧发布；后续发布见[项目发布语义规则](../project_release/semantic_constrains.md)。

## 规则

| ID | 工程判据 | 评审依据 |
| --- | --- | --- |
| WI-SEM-001 | 工程解释保留用户想达成的结果和关键限制，没有把偏好的实现手段误当唯一意图，也没有扩大任务范围。 | 原提交与解释差异 |
| WI-SEM-002 | 使用者、情境、预期结果与问题足够清楚，能够讨论可行方案；涉及未知内容时，其影响可解释。 | 使用场景、来源及问题 |
| WI-SEM-003 | 验收意图能说明用户希望观察到什么结果，尚未量化的阈值明确待后续需求阶段细化；此时不伪造最终验收证据。 | 意图、场景与待细化项 |
| WI-SEM-004 | 限制、非目标、假设和冲突诚实披露；关键矛盾未解决时不能宣称充分清晰。 | 约束、假设、冲突处置 |
| WI-SEM-005 | 来源与确认程度可信，AI 推断、用户原话、外部资料和实际回答可区分；无需虚构访谈来支撑意图。 | 来源与澄清记录 |
| WI-SEM-006 | Wish 的范围和增量划分有理由，首个增量具备可评价目标；暂缓的部分继续可追溯，不能被无说明丢弃。 | 增量目标、范围与追溯 |
| WI-SEM-007 | 工作上下文和引导基线足以进行评估，项目 T1 或首次最小引导机制的有限来源、固定依赖与已做检查清楚；不以自举声明证明产品已验收。 | 输入基线、工具与规则选择 |
| WI-SEM-008 | 独立 Wish 模型准确关联其影响的项目元素，共享材料的引用有相关理由；已有其他 Wish 的通过不能代替本条解释。 | Wish 链、项目元素、共享引用 |
| WI-SEM-009 | 开放问题对可行性评估的影响可接受且有处理路径；阻塞性用途或约束缺失时等待澄清，而不是默认放行。 | 问题、责任和影响 |
| WI-SEM-010 | “充分清晰”的理由限定在进入可行性评估的准备程度，不等价于系统需求完整、关卡通过或产品完成。 | 准备判断、下一工作 |
| WI-SEM-011 | 工具绑定能支持本项目全生命周期的语言处理、阶段位置、渲染与追溯，固定的是机制，后续新增 Wish、项目 view、追溯内容和用户规则仍可演进。将新增业务 Wish 当作重选内核的理由、用 T2 候选自动替换 T1，都不满足初始化边界。 | 项目工具与依赖绑定、核心目标、固定机制与可变资产划分。 |
| WI-SEM-012 | 继承发布开展新工作时，应识别原成果、工具及约束的适用范围，当前解释/修订形成新开发资产；历史判断保留真实依据，不冒充当前材料的重新评审。当前 Wish 涉及发布隔离时，澄清出 R1 后修改并形成 R2、R1 仍不变且能用原 T1 读取的预期结果，细化判据留给需求阶段。 | 继承范围、历史依据及适用性、开发修订、发布隔离意图。 |

## 出口与返工

分别记录清晰性判断与上下文准备事实。充分时进入 `AssessFeasibility`，不足时按现有流程停在 `holdForAuthority`，补充来源/解释或调整范围后重新判断。用户修订建立新的开发材料选择，原提交与既有解释继续保留，旧发布只读不变。

## 判定示例

充分：用户希望每条 Wish 能独立解释从意图到证据的路径，澄清出共享设计和用户修改决定的限制，记录尚待量化的展示细节后进入可行性评估。

不足：把“支持受控工作流”直接改写为“所有关卡强制人工批准”，遗漏用户允许人或 AI 担任 AGENT 的意图；或把未回答的问题当作已确认。
