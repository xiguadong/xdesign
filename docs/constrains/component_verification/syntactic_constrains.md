# 组件验证阶段的语法与结构约束

规则集版本：0.1。日期：2026-10-12。状态：目标约束。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围及依据

本规则用于 `componentVerification` 阶段实际提交的组件验证模型、材料、执行证据和审查包。该阶段通过 `Component review` 判断实现的组件是否符合选定详细设计，下一工作为 `integrationVerification`。规则可作为机械检查的判定标准，不表示仓库已经实现对应检查器。名称、类型、引用等语言层检查在本目录归入语法与结构合规；通过本规则不等于关卡通过。

依据：[整体架构设计](../../../design/workflow_mbse_architecture.md)（0.2）的“生命周期中的内容分类”“两个区域的操作边界”“用户约束如何演进”，[V-model 定义](../../../v_model_agents.sysml)的 `ComponentVerificationAgentBehavior`、`componentVerifiesDesign` 和 `Component review`，以及 [Wish 生命周期模型](../../../wish_to_product.sysml)的 `ComponentVerificationSpec`、`ComponentVerificationBundle`、`Evidence`、`ProducedBundle`、`ContractedVModelDevelopment::componentVerification`。

通用要求见[路由说明](../README.md)、[模型与追溯语法约束](../model_traceability/syntactic_constrains.md)、[工作流执行语法约束](../workflow_execution/syntactic_constrains.md)；工程判断见[本阶段语义约束](semantic_constrains.md)。

## 输入、允许工作与产出

本阶段的模型、材料、实际证据、检查及新决定写入开发区持久资产/记录；从已发布成果继承时只读选定内容。用户修改结果新增开发决定，旧发布内的内容、原规则选择、决定及证据不变。提交发布时再按[项目发布语法约束](../project_release/syntactic_constrains.md)选择依赖并创建新的不可变发布，本阶段关卡不替代发布操作。

输入包含明确的 wish、增量与尝试范围，当前实现与构建基线，选定详细设计基线及组件验证用例/程序，以及本次使用的流程、定义库和规则版本。实现基线是阶段顺序上的输入；详细设计是被验证的工程依据，两者都应保留在审查包依赖清单中。

允许执行组件验证、收集日志和观测、登记异常、补充执行环境及证据引用、更新验证结果模型与 wish view。发现设计或实现需要变化时，提出变更并按受影响阶段返工；不能在同一证据记录中悄悄改写设计或被测构建。

必须提交组件验证模型、用例与详细设计的关系、实际运行记录和原始日志引用、逐用例结果、覆盖与缺口清单、异常及处置报告、版本清单、结构检查结果和 `Component review` 审查包。现有模型未提供的执行状态、环境和历史字段，应在阶段契约选定的结构化附属记录或明确类型的模型扩展中表达；以下规则约束这些记录的内容，不假定新增字段已存在。

| CV-SYN-010 | 审查包固定组件构建、详细设计、用例、执行证据、规则、依赖和未决问题版本；决定可定位判断者及其 kind、授权范围、理由、证据和审查包。项目绑定的初始模板中 `gateId` 为 `Component review`，申请的 `permittedNextWork` 为 `integrationVerification`；其他项目模板在初始化时固定，不在本阶段更换关卡位置。 | 审查包清单、`ReviewDecision`、workflow AGENT 配置。 |
| CV-SYN-011 | 相关设计、构建、程序、环境或规则变化具有变更记录和受影响证据/决定清单；旧证据复用时保留原执行输入、规则及上游设计/实现版本，新增版本差异、复用范围及适用性评估；不将旧记录的 `checkedBaselineId` 改为最终发布基线。返工形成新尝试；用户修改关卡结果新增替代决定并保留原检查与失败记录。 | 变更影响清单、尝试历史、决定替代关系。 |
| CV-SYN-012 | 当选定详细设计规定组件承担工具绑定、保存、候选封存或历史读取职责时，用例/覆盖表包含 T1 固定绑定、开发写入与发布只读、候选内容隔离、失败封存无成功发布等目标；为 R1 发布后开发修改与 R2 发布的上层验证提供组件证据入口，不强制把完整系统场景归为组件执行。 | 详细设计—组件用例—结果映射、保存/读取与封存记录。 |

## 出口与返工

结构缺项或错误应报告为可定位诊断，修正记录后重新检查。已完成机械检查的审查包交给 workflow 配置的人或 AI AGENT 进行语义判断；协调器依据当前有效 `Component review` 决定、产物契约和输入适用性安排后续集成工作。

组件失败可能要求返回实现、详细设计或更早受影响阶段；由变更影响评估确定流程中声明的返工位置，保留每次尝试。没有实际观测或结果不确定时保留等待/不确定状态，先核对或重新执行，不能用默认成功推进。

## 例子

合格：`CV-RUN-17` 引用构建 `BUILD-42`、详细设计 `DD-12@3` 和程序 `CASE-8@2`，登记工具与夹具版本、输入、观测及日志摘要；结果失败并链接 `ANOM-6`。修订后的 `CV-RUN-18` 通过且引用前次记录，覆盖表显示两个状态，审查包保留处置与复验链。该记录结构合格，是否允许集成仍由关卡判断。

不合格：Bundle 中仅有“全部单测通过”的文档和用例定义，将断线后未知的运行标为 `passed=true`；日志指向当前可变目录，缺少被测构建及程序版本。违反 CV-SYN-002、004、005、006、008，不能提交为已完成的组件验证证据。
