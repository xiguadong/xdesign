# 实现与构建：语法校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围、输入与产出

对应 `implementation`、`ImplementationSpec/ImplementationBundle` 和 `Build review`。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)与[产物契约](../../../wish_to_product.sysml)，遵循[公共规范](../README.md)、[模型规则](../model_traceability/syntactic_constrains.md)及[运行规则](../workflow_execution/syntactic_constrains.md)。本文规定目标校验，不声明构建已经执行。

输入为选定 CDR 的组件设计、接口/记录规范、组件验证规程、需求与架构引用、源码/依赖/工具配置。允许在开发区范围内实现、保存受控源码、执行构建和必要静态检查、更新实际组件配置与实现关系；从旧发布继承时只读原成果，修订产物以新版本写入开发区，偏离设计进入影响和返工。工具项目可以生产 T2 候选，但执行本次工作的 T1 不随候选改变。输出为源码选择、构建说明与清单、实际构建产物、日志、配置记录、实现追溯及原生 view。

## 规则

| ID | 约束与判定方法 | 诊断位置 |
| --- | --- | --- |
| BUILD-SYN-001 | 运行及构建选择能定位 Wish/增量/尝试、CDR 设计、接口、组件用例、需求/架构和规则版本；实际源码与生成产物关联同一选择。 | 输入、构建清单、基线 |
| BUILD-SYN-002 | 源码使用所属语言/仓库的文件与结构规范，构建说明、清单和配置记录按公共命名或工具标准保存；工具配置不因 Markdown 命名规则被强制重命名。 | 源目录、配置文件、说明 |
| BUILD-SYN-003 | 实际 as-built 原生模型描述组件 usage、配置、版本和实现引用，可解析并有本阶段 view；声明一个预期构建包不能替代实际组件/文件。 | 原生模型、配置与产物身份 |
| BUILD-SYN-004 | 实现引用从源码/模块/构建单元映射到具体设计元素，端点、角色和版本合法；共享实现保持单一来源，需求路径可追溯。 | 实现关系、设计映射 |
| BUILD-SYN-005 | 清单固定源码提交或可恢复快照、实际改动、产品构建依赖/工具版本、构建参数和配置，并核对本项目执行机制等于初始化绑定 T1 及固定依赖；运行前后材料变化报告冲突，不只记录可变分支名或 `latest`。 | 源快照、依赖、内容摘要 |
| BUILD-SYN-006 | 构建说明包含环境前提、依赖准备、命令/步骤、输出位置及判定标准，产物能用身份与摘要定位；无需依靠未记录的本机手工状态。 | 构建说明与输出清单 |
| BUILD-SYN-007 | 构建及契约要求的静态/语言检查真实执行，记录输入版本、工具、时间、日志、退出/观察结果和诊断；未运行、失败、未知不得记为成功。 | 构建日志、检查记录 |
| BUILD-SYN-008 | 模型/代码/接口类型及配置引用进行适用检查，结果与被检查源码一致；编译不检查的运行接口、生成配置和外部资源保留独立检查入口。 | 编译诊断、接口及配置检查 |
| BUILD-SYN-009 | 候选产物、开发资产保存、运行记录提交与发布封存分别有身份和结果；候选内容及依赖固定后不跟随开发编辑，更换选择建立新候选。发布只创建新的不可变对象，失败/未知封存不登记成功，旧发布不得覆盖，恢复所需未完成产物不能仅存缓存。 | 候选、保存、采纳与冲突记录 |
| BUILD-SYN-010 | 构建失败、警告、偏离设计和未解决问题可定位到版本、原因及处置；早期构建/检查保留其真实源码、输入和规则选择，复用形成适用性评估，不重标为最终发布内容执行；修改设计经受影响阶段重审，不能在实现记录中隐式改写 CDR。 | 问题、设计差异、历史 |
| BUILD-SYN-011 | `Build review` 包固定源码、构建配置/产物/日志、追溯、结构结果和问题；有效决定准许 `componentVerification`，不写入未来组件验证成功；用户修改结果新增开发决定，旧发布内的决定与证据不变。 | 审查包、决定与下一工作 |
| BUILD-SYN-012 | 用户语法/阶段约束 SysML、语义约束 SysML、文档规则及外部规范选择有版本清单；新尝试显式采用修订版本，已执行检查保留原选择。实现涉及保存/发布时，设计—实现映射覆盖 T1 固定、开发写入、候选内容固定、旧发布只读及 R1/R2 隔离的验证入口。 | 约束版本清单、尝试与实现映射、保存/发布接口。 |

## 出口与返工

完成真实构建及适用结构检查后执行[语义评审](semantic_constrains.md)。正常放行进入组件验证，源码/环境问题在本阶段返工；设计不足返回详细设计，架构/需求问题沿影响范围返回上游。用户例外只改变开发区指定范围的决定，缺失产物和不可用适配器仍是运行前提问题。发布操作遵循[项目发布语法规则](../project_release/syntactic_constrains.md)，不新增 V-model 阶段；Build review 不替代发布封存及其记录。

## 判定示例

合格结构：清单固定源码快照、JDK/依赖版本、参数、实际 JAR 摘要与构建日志，as-built 模型关联该配置和组件设计。

不合格结构：只有“构建完成”文字或预期产物声明，没有实际输出与日志；或已有源码改动却把上一提交的构建结果归到当前代码。
