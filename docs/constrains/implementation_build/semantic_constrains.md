# 实现与构建：语义校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

适用架构：[整体架构 0.2](../../../design/workflow_mbse_architecture.md)。项目初始化绑定工具发布 `T1` 及固定依赖：V-model、公共元模型、编译/解析、渲染和追溯机制在项目生命周期内保持不变，工具升级另行迁移。用户语法/阶段约束 SysML、语义评审约束 SysML、文档规范及外部规则可以发布新版本，新尝试显式采用；既有证据和决定保留原选择。

## 适用范围与评审输入

对应 `Build review` 对实现、构建及配置符合性的判断。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)和[公共规范](../README.md)，同时应用[模型语义](../model_traceability/semantic_constrains.md)、[运行语义](../workflow_execution/semantic_constrains.md)。workflow 配置的 AGENT 审查同一选择上的设计、实际源码、配置/构建产物、日志、结构结果及问题，不以规范文档代替评审。

允许评价开发区实现的符合性、构建可重复性及验证准备，提出返工；输出为逐项理由和本关卡建议。继承旧发布只读，评审及用户替代决定新增开发记录。相关封存边界见[项目发布语义规则](../project_release/semantic_constrains.md)。

## 规则

| ID | 工程判据 | 评审证据 |
| --- | --- | --- |
| BUILD-SEM-001 | 实现兑现选定设计的关键责任、接口、不变量与行为；存在映射不等于内容一致，偏离有工程理由和适用决定。 | 设计与源码/配置差异 |
| BUILD-SEM-002 | 实现包含适用的失败、取消、版本冲突、重复请求和恢复路径，没有把设计中的关键行为保留为运行占位或默认成功。 | 行为代码、失败路径、设计约束 |
| BUILD-SEM-003 | 原生模型、库与实际工具选择一致，执行机制维持初始化绑定 T1 的 V-model、公共元模型、解析/渲染/追溯与固定依赖；T2 候选不替换当前内核，既有项目升级单独迁移。适配器输出语言/类型诊断和支持范围，不将工具解析成功夸大为产品功能已完成。 | 工具绑定、语义适配、诊断 |
| BUILD-SEM-004 | 检查、AGENT 及用户决定的实现保持事实边界，返回值/默认 Boolean 不伪装实际评审，授权和范围正确参与推进，用户修改只新增开发决定而不回写已发布决定。 | 检查与决策实现、记录协议 |
| BUILD-SEM-005 | 实际持久化、身份绑定、历史选择和 view 更新符合设计：保存只写开发资产，候选内容固定，封存只产生新的不可变发布，失败/未知状态不冒充成功，旧发布只读且损坏可诊断。派生缓存不能成为原生资产、已发布成果或恢复所需事实的唯一保存处。 | 存储/采纳实现、记录与模型 |
| BUILD-SEM-006 | 构建配置产生所审组件而非无关或旧输出，依赖和生成材料可解释；构建方式能在记录的环境重现关键产物与配置。 | 清单、产物摘要、实际构建结果 |
| BUILD-SEM-007 | 环境相关配置、外部依赖和运行 profile 与后续组件验证一致，验证者能获得所选产物及观察入口。 | 运行前提、配置和验证规程 |
| BUILD-SEM-008 | 编译/静态检查支持其实际覆盖的性质，AGENT 说明它们不能证明的设计行为；成功构建不自动等价组件验证通过。 | 检查范围、日志、待验证主张 |
| BUILD-SEM-009 | 实现复杂度、资源和性能取舍符合设计约束，新增依赖与扩展没有在未评估时成为必须前提。 | 实现方案、约束和依赖差异 |
| BUILD-SEM-010 | 失败、警告、未实现项和设计差异的影响已评价，给组件验证的限制和剩余问题明确；关键缺口不能只承诺以后补齐。 | 问题处置、覆盖缺口、下游准备 |
| BUILD-SEM-011 | 放行理由仅支持选定实现进入组件验证，明确需要后续实际证据；历史构建和共享代码不会使其他版本/Wish 自动通过；早期证据保留真实输入/规则及支持范围，依据适用性复用而不重标为针对最终内容执行。 | 关卡范围、版本与下一工作 |
| BUILD-SEM-012 | 对选定设计中的发布隔离主张，实现应提供可验证的路径：R1 后修改用户约束、模型、文档及决定再发布 R2，R1 内容/决定/依赖保持原状且可由原 T1 读取/展示。边界、失败与冲突路径不允许开发保存、规则演进或新工具候选改写 R1；本阶段只判断实现与验证准备，完整成立仍需后续实际验证。 | 保存与封存实现、版本绑定、读写边界、失败处理、组件/集成/系统验证准备。 |

## 出口与返工

AGENT 给出 `pending/approved/rework/rejected` 建议，当前有效决定准许 `componentVerification`。实现/配置问题在本阶段修复，设计根因返回 CDR，关键架构根因回 PDR。用户替代决定按公共协议保留原事实并传递限制；未来组件、系统验证与验收仍分别判断。

## 判定示例

充分：源码按设计保存尝试身份与输入，恢复使用同一记录；真实构建清单让组件验证选择同一产物，AGENT 指出尚待验证的恢复行为。

不足：JAR 已生成但协调器仍把 `productionContractSatisfied=true` 当作全部检查完成；或失败路径仅返回成功字段，掩盖未实现的记录保存。
