# 详细设计：语义校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围与评审责任

对应 CDR 对组件设计及验证准备的充分性判断。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)与[index](index.md)，采用[公共协议](../README.md)及两个全阶段目标的语义规则。输入为选定 PDR/需求、详细设计、组件模型/用例、实际结构诊断和问题；由该 workflow 配置的人或 AI AGENT 判断。文档本身不代表已做评审。

允许评价可实现性、设计一致性和可验证性，提出根因及返工阶段；输出为有证据的 CDR 建议。

## 规则

| ID | 工程判据 | 评审依据 |
| --- | --- | --- |
| DD-SEM-001 | 详细设计忠实展开选定架构与需求，组件责任和边界足够具体；架构变更有影响与重审依据。 | 上游设计、组件职责与差异 |
| DD-SEM-002 | 实现者无需自行发明关键接口、数据不变量或状态语义，即可按设计构建组件；未确定实现细节有边界与选取条件。 | 接口/数据/状态、开放问题 |
| DD-SEM-003 | 正常、失败、取消、边界与恢复行为相容，条件和状态变化能够解释实际使用，不出现无责任的错误或不可恢复状态。 | 行为模型、异常路径、用例 |
| DD-SEM-004 | 数据与记录身份、引用、版本和维护来源足以保持工程事实与历史一致；候选、采纳、观察和决定不会互相混淆。 | 记录规范、来源和状态 |
| DD-SEM-005 | 涉及 Git 与 ProjectStore 保存时分别处理冲突和部分成功，采纳记录能关联两边真实结果；没有假设跨来源操作天然原子成功。 | 保存协议、版本检查、恢复点 |
| DD-SEM-006 | 重复请求、暂停重启和不确定外部效果的处理避免事实复制或盲目重复执行，且保留已有产物和观察。 | 去重/恢复设计及异常用例 |
| DD-SEM-007 | 语法结果、语义评估、AGENT 决定及用户替代决定的交接具体且正确；用户可改变有效关卡结论，但不把原检查或观察事实的失败改写为通过，不绕过不可执行前提。 | 关卡接口、替代记录、推进条件 |
| DD-SEM-008 | 关系、共享身份、原生 view 和外部章节定位的细节能维护独立 Wish 链，展示不会丢掉影响当前结论的历史与失败。 | 追溯设计、定位和展示契约 |
| DD-SEM-009 | 算法、支持 profile、资源和性能取舍有适用依据，依赖接口可用；声明不支持的行为有明确诊断和限制。 | 算法说明、约束、工具依赖 |
| DD-SEM-010 | 组件用例能辨别设计是否真正满足，覆盖关键不变量、异常、边界和恢复；判据不能只重复实现步骤或仅检查返回成功。 | 设计主张、用例和覆盖缺口 |
| DD-SEM-011 | 验证环境、数据和可观察输出可获得，测试准备足以进入实现/构建及后续组件验证；模拟限制和尚缺依赖有处置。 | 环境方案、规程、依赖准备 |
| DD-SEM-012 | 剩余问题与假设对实现的影响已说明，CDR 准许范围与实际准备一致；不能以未来会补齐的关键设计支撑无条件放行。 | 问题处理、风险、下一工作 |
| DD-SEM-013 | 组件契约能落实固定工具与可变用户规则/项目内容的边界；机器或候选工具变化不自动改变 T1，规则可显式换版且不改已发布对象。 | 初始化、加载、规则扩展与来源设计 |
| DD-SEM-014 | 候选核对、封存、只读访问、损坏诊断及保留设计足以保证 R1 不受后续开发/R2 影响；用例能检出错误原位保存、错误依赖和虚假成功发布，不只检查返回字段。 | 发布协议、异常恢复、隔离用例及判据 |

## 出口与返工

CDR 建议使用公共结果与理由，批准范围限定所选设计的 `implementation`。关键责任/接口缺口回架构，组件内部或用例不足在详细设计返工；无法判断时补依据后再审。用户范围内替代决定保存原不足并给下游明确限制，后续构建和验证仍需真实结果。

## 判定示例

充分：协调器说明提交前保存尝试、重启后按同一身份恢复、不确定执行先核对，并为这些路径制定有观察判据的组件用例。

不足：只规定“失败自动重试”，却不能确认外部动作是否已经发生；或测试仅断言存在一条批准字段，未检查其范围、材料与下一工作。
