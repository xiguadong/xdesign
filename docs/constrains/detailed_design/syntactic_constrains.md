# 详细设计：语法校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围、输入与产出

对应 `detailedDesign`、`DesignSpec/DesignBundle` 和 CDR，依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)及[产物定义](../../../wish_to_product.sysml)。同时应用[index](index.md)、[原生模型](../model_traceability/syntactic_constrains.md)与[运行记录](../workflow_execution/syntactic_constrains.md)规则。本文是目标规范。

输入为当前 Wish、选定需求、PDR 架构/接口/集成计划和决定、项目固定工具/流程及用户规则选择。允许在开发区展开组件结构、行为、数据和异常契约，制定组件用例及更新关系/view；不修改固定工具或旧发布。上游架构变更必须进入影响与返工路径。

## 规则

| ID | 约束与判定方法 | 诊断位置 |
| --- | --- | --- |
| DD-SYN-001 | 本次输入固定需求与 PDR 架构、接口、决定及规则版本，详细设计映射到同一 Wish/增量/尝试与组件身份。 | 输入、身份与上游引用 |
| DD-SYN-002 | 文件命名与内容映射符合 index；结构、接口、行为、数据、异常、约束、追溯和验证准备可定位，适用内容不能以占位符代替。 | 文档、章节和产物清单 |
| DD-SYN-003 | 组件原生模型实际解析成功，定义/usage、内部结构、行为和约束合法；组件与上游部件/接口引用可解析。 | 模型、类型、工具诊断 |
| DD-SYN-004 | 组件设计元素映射至需求、架构部件和接口，适用 satisfy 与细化/分配关系可检查；共享设计维持同一身份和来源。 | 关系、覆盖矩阵、身份绑定 |
| DD-SYN-005 | 接口列出操作/事件、输入输出类型、前后条件、效果和失败/取消结果，与架构接口方向及类型可比较；变更明确记录。 | 接口契约、差异与变更项 |
| DD-SYN-006 | 数据/记录规范声明身份、类型、必需性、引用、版本、维护来源与持久化选择；不适用项附理由，不能以空字段模拟已有事实。 | 数据表、记录约束、来源 |
| DD-SYN-007 | 行为有入口、分支条件、状态及出口，不变量与边界可定位；适用的超时、取消、重试、去重和恢复路径有设计表达。 | action、状态图、行为说明 |
| DD-SYN-008 | 涉及多来源保存或外部效果时，分别说明版本检查、部分成功、冲突和不确定效果的记录/恢复责任；设计不能把缓存作为唯一恢复位置。 | 保存/恢复设计、异常路径 |
| DD-SYN-009 | 每个组件验证用例有身份、所检查设计元素、配置/环境、输入、步骤、预期、通过判据和证据要求；计划与未来执行结果分开。 | 组件用例、verify/角色关系 |
| DD-SYN-010 | 关键设计路径及边界/异常有覆盖关系，缺口进入问题清单并注明影响、责任、处置；必需用例不以 `TODO` 占位满足契约。 | 用例覆盖、问题记录 |
| DD-SYN-011 | 组件与 Wish 的原生 view 展示本阶段设计、约束和验证准备；模型、规范、伪代码的规范性/版本及引用一致可定位。 | view、文档/模型映射 |
| DD-SYN-012 | CDR 审查包固定设计、规范、用例、关系、检查和问题；当前有效决定准许 `implementation`。相关设计变更新建选择，不沿用旧 CDR 作为新版本批准。 | CDR 包、决定和适用性 |
| DD-SYN-013 | 初始化与规则接口设计区分固定工具依赖/公开元模型和用户约束 SysML，日常工具绑定不可改；约束版本与规则结果绑定，已有发布规则保持原选择。 | 初始化/规则契约、版本和访问边界 |
| DD-SYN-014 | 发布/存储设计声明候选与最终决定独立身份、内容核对、封存新对象、只读拒绝和损坏诊断；用例关联发布隔离、封存失败、共享依赖保留与缓存不覆盖主张。 | 发布记录设计、写入契约、组件用例 |

## 出口与返工

结构结果交给[语义评审](semantic_constrains.md)。正常进入实现需当前 CDR 对所选设计有效；用户例外依公共协议限定。组件设计缺口在本阶段修复，架构接口或责任根因回 PDR，需求根因回 SRR；每次建立新尝试并保留原诊断。

## 判定示例

合格结构：存储组件规范有记录身份、版本检查、冲突输出、恢复点和相应组件验证用例，各自指向同一架构组件。

不合格结构：详细设计只有架构图，没有字段、状态或失败条件；或组件用例只写“测试成功”，缺少输入、判据与设计端点。
