# 工作流、关卡与运行记录：语义校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围与责任

适用于阶段契约是否可执行、关卡材料与决定是否充分、用户规则演进、发布边界与恢复是否符合工程意图。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)，使用[公共协议](../README.md)。输入为项目固定流程、阶段契约、产物和实际执行/检查/决定历史；关卡 AGENT 可以由人或 AI 担任，逐项判断的材料必须与语法检查选择一致。

允许审查、要求补充和提出影响范围；输出为有理由的关卡建议或用户替代决定的适用性评估。此文档规定判断准则，不预置运行结果。

## 规则

| ID | 工程判据 | 评审依据 |
| --- | --- | --- |
| WF-SEM-001 | 阶段契约的输入、允许动作与产出能完成本阶段工程职责，出口与下一工作衔接充分；不能用“生成文档”概括应解释的需求、设计或证据责任。 | 契约、阶段目标、上下游产物 |
| WF-SEM-002 | 选定关卡在当前模板中承担正确主题，PDR 判断方案/架构，CDR 判断详细设计/组件验证准备，右侧验证分别对照左侧基线。模板迁移差异有明确解释。 | 流程版本、关卡职责、迁移映射 |
| WF-SEM-003 | 审查包包含影响结论的正反证据和未解决问题，足以重建判断上下文；当前 UI 选择或生产者一句“已完成”不足以支持。 | 审查选择、实际材料、问题清单 |
| WF-SEM-004 | 检查事实、语义判断、有效决定与运行状态各有解释。AGENT 判断说明工具通过能支持哪些内容，以及仍需判断哪些充分性问题。 | 逐项检查、评审理由、推进记录 |
| WF-SEM-005 | 主体对当前范围有明确责任和授权，人工接管、授权失效及用户修改能够影响有效决定。是否安排同一主体生产和评审由 workflow 说明，不能因主体是 AI 自动禁止或自动批准。 | workflow 配置、权限选择、决定来源 |
| WF-SEM-006 | 决定理由回答本关卡的工程问题，明确已满足内容、缺口、不确定性与允许工作；泛化的“符合要求”不能替代具体依据。 | 决策主题、规则结果、证据引用 |
| WF-SEM-007 | 例外或用户修改具有可解释的范围和影响，后续执行理解剩余风险与受限动作；修改关卡结论不声称失败事实消失、产品已完整验证或缺失材料已产生。 | 替代决定、例外依据、后续限制 |
| WF-SEM-008 | 返工回到能修复根因的最早受影响阶段，保留新旧尝试对应；只重跑最后失败测试无法修复需求或架构根因时，应提出上游变更。 | 根因、依赖影响、返工路径 |
| WF-SEM-009 | 相关变更使对应主张与决定重新评估，无关范围继续可用；变更规则通过显式选择生效，历史判断不按新标准回写。 | 选择差异、影响分析、适用性决定 |
| WF-SEM-010 | 暂停、取消和恢复能解释实际活动与外部效果；恢复不会遗漏已发生工作或因盲目重试造成重复效果。不确定性先核查，再决定继续方式。 | 状态历史、外部观察、恢复理由 |
| WF-SEM-011 | 完成判断分别评价每条 Wish 的意图、选定工程链、真实证据及完成契约；流程结束、所有文件存在和结构通过不足以证明产品已满足用途。 | Wish 完成包、验收/移交范围、剩余问题 |
| WF-SEM-012 | 工具自举保留固定执行机制，候选成果经验证形成下一工具发布；验证覆盖结构与语义分离、人/AI、用户修改、变更、共享 Wish、恢复及发布隔离。业务场景不能代替这些能力证据。 | 固定工具/引导选择、候选工具验证、发布历史 |
| WF-SEM-013 | 用户规则演进与固定流程机制分离，显式采用规则不会移动关卡或升级工具；旧发布内的规则、判断及证据仍保持原内容，新决定只重算开发工作。 | 规则/工具版本、影响范围、R1/R2 对照 |
| WF-SEM-014 | 发布决定针对确定候选，早期证据保留各自真实输入/规则并说明当前适用性；选择只保留所需依赖而可独立解释成果。发布完成与阶段通过分别有真实记录。 | 候选、证据选择、最终决定与封存结果 |

## 出口与返工

把适用性、理由、缺口和不确定性保存到逐项评审；设有关卡时再作 `pending/approved/rework/rejected` 决定，无关卡动作按固定流程保存准备事实与条件并推进。旧判断不适用时保留为历史并组织新审查；例外按公共协议追加，不能改写真实检查。需要返工时给出阶段、受影响材料和新的审查要求。

## 判定示例

支持充分：模型结构通过，但 AGENT 发现接口失败时的恢复责任没有设计，CDR 给出返工理由并返回详细设计；补充设计后建立新尝试和审查包。

支持不足：协调器看到解析退出码 0 就自动批准 CDR；或用户批准一个范围内的例外后，系统把整条 Wish 标为全部验证通过。
