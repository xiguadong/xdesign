# 工作流、关卡与运行记录：语法校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围与输入输出

适用于固定流程、workflow usage、阶段尝试、用户规则、检查、审查包、AGENT 决定、用户替代决定及恢复记录。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)“固定工具与项目环境”“用户约束如何演进”；流程位置参考 [VModelDevelopment](../../../v_model_agents.sysml) 和 [WishToProductLifecycle](../../../wish_to_product.sysml)。遵循[公共协议](../README.md)，这些规则是目标规范。

输入为选定的流程/库/规则版本、阶段契约、Wish 范围、源基线、可用适配器及已保留记录。允许调度契约内工作、检查和判断，追加尝试与观察、暂停恢复、执行明确的返工；输出为可恢复的运行状态和完整的事实/决定历史。

## 规则

| ID | 约束与判定方法 | 诊断位置 |
| --- | --- | --- |
| WF-SYN-001 | 运行核对项目固定工具/流程/公共元模型，显式选择用户规则、Wish/增量及输入依赖版本，启动前能恢复选定内容。新规则进入变更候选，不在执行中替换正在检查的标准。 | 项目绑定、运行选择、启动诊断 |
| WF-SYN-002 | 每个阶段契约声明输入、允许工作、必需产物与关系、view、结构检查、语义责任、关卡出口及返工路径；产物位置和适配器绑定能解析。 | 契约与绑定 |
| WF-SYN-003 | 按选定模板解释阶段、关卡、分支和下一工作。初始模板只支持顺序、条件分支、AGENT 关卡、显式返工、暂停恢复等已声明 profile；不支持语义报告错误，合法返工环不按 DAG 拒绝。 | 原生 action/succession、执行 profile |
| WF-SYN-004 | 普通工作与关卡分别记录执行者/判断者、主体种类、身份、授权范围和人工接管配置。workflow 自行配置，不填入一个隐式全局人工或 AI 审批默认值。 | workflow usage、主体及授权选择 |
| WF-SYN-005 | 调度前保存运行和尝试身份、阶段、实际输入、允许动作；执行输出、未解决问题及变更关系关联该尝试。失败和返工建立新尝试，不能覆盖原观察。 | 尝试记录、调度记录、输出清单 |
| WF-SYN-006 | 审查包有身份及可重建版本清单，包含范围、上下游材料、关系、规则、检查结果、语义依据、问题及请求的下一工作；UI 当前选中对象不能替代审查包。 | 审查包与内容摘要 |
| WF-SYN-007 | 每项检查保存规则和版本、输入选择、执行主体/工具、时间、结果及定位诊断。未执行、工具错误、不适用与通过分别表达；不以 `syntaxPassed`、`semanticsPassed` 等默认值代替记录。 | 检查记录、工具输出、规则绑定 |
| WF-SYN-008 | 决定包含身份、判断者与种类、授权范围、关卡、审查包、结论、理由、证据及允许的下一工作；范围、版本与请求必须匹配。`approved` 字段存在不足以构成有效放行。 | 决定、授权、审查包引用 |
| WF-SYN-009 | 用户修改追加替代决定，关联被替代决定、修改者、原因、材料选择、例外规则/范围和下一工作。原检查失败、未运行结果及历史决定保留；当前有效选择可唯一定位。 | 替代关系、例外清单、有效决定选择 |
| WF-SYN-010 | 分别保存运行状态、结构结果、语义结论及有效关卡决定。有关卡时核对当前决定/例外范围，无关卡步骤核对固定流程的准备条件；调度前均须检查输入可读、流程可解释及适配器可用。 | 推进依据与运行前提 |
| WF-SYN-011 | 相关输入/关系/规则变更生成新选择和影响记录，标识受影响决定适用性；历史内容可恢复。源文件与存储记录保存分别做版本检查，采纳记录关联各自提交结果与冲突。 | 依赖、版本冲突、采纳记录 |
| WF-SYN-012 | 暂停后阻止后续调度；取消记录已停止活动与已发生效果；恢复使用原运行及尝试身份。重复请求不重复创建已提交事实，对外部效果不确定的尝试先核对再重试。 | 状态事件、去重身份、外部效果观察 |
| WF-SYN-013 | 完成决定明确 Wish、增量、完成契约和需求/设计/实现/验证/使用确认及必要移交的选择。流程结束或工具退出码不自动写入完成决定，多 Wish 各有判断范围。 | 完成审查包、完成决定 |
| WF-SYN-014 | 工具发布/固定依赖绑定在项目生命周期保持不变，机器升级不改变项目；候选工具或 V-model 作为开发成果，不自动接管当前执行。升级须单独迁移设计。 | 工具锁定、执行环境、迁移边界 |
| WF-SYN-015 | 用户约束 SysML 和文档规范换版有身份、版本、选择范围与实际记录；使用固定公共元模型及扩展接口，不移动关卡。已开始检查保持原规则，重评建立新检查与决定。 | 用户规则源、选择与评审历史 |
| WF-SYN-016 | 阶段输出/新决定写开发区，发布按[发布规则](../project_release/syntactic_constrains.md)核对候选并封存新对象；候选、决定、封存结果身份分开，旧发布和包内证据只读。 | 区域写入、候选/发布记录 |

## 出口与失败处理

检查结果交给同一审查包的[语义评审](semantic_constrains.md)。缺失记录、授权或不支持的执行表达须定位诊断并等待补齐、换适配器或按流程返工。用户能够修改关卡结果，但运行前提未成立时仍不能调度，并保存“有效决定存在、当前无法执行”的原因。

## 判定示例

合格记录：CDR 的决定选择设计 v3、组件验证计划 v2、规则集 0.1 和本次检查，准许 `implementation`；重启后仍恢复到此决定和尝试。

不合格记录：只保存 `approved=true`，没有审查包；或用户改为通过后把原失败日志删除；或崩溃后不核对已有发布效果就重跑发布动作。
