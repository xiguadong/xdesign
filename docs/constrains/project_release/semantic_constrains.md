# 发布候选与不可变成果：语义校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围与评审依据

适用于是否采纳特定候选为发布、冻结边界是否充分及发布后独立读取是否可靠的工程判断。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)，遵循[公共协议](../README.md)与两个全阶段目标。AGENT 可以是人或 AI，按 workflow 配置责任和授权。此文档不代表发布检查或判断已经实现。

输入为固定候选、工具/用户约束、工程成果与原生关系、证据各自的输入/规则、当前检查、阶段/完成决定、依赖保留和封存设计/实际结果。允许判断充分性、提出缺口/限制和拒绝封存；输出为逐项依据与限定候选的发布建议。封存后的核查提供实际发布完整性证据，不额外移动原关卡。

按时点选择规则：候选评审不要求尚未发生的封存结果；REL-SEM-009 在封存后核查实际效果。REL-SEM-010 用于工具项目发布隔离能力的验证，普通项目采用固定工具已有的能力证据，并核对本次发布的实际边界；首次 R1 不等待本项目未来 R2 才获批准。不适用/尚未执行的结果及理由分别保存。

## 规则

| ID | 工程判据 | 评审依据 |
| --- | --- | --- |
| REL-SEM-001 | 发布范围准确表达本次要交付的 Wish、部件和成果，独立范围分别有判断；“整个项目已完成”等扩大结论必须有相应完成契约与证据。 | 范围、Wish 完成选择、交付意图 |
| REL-SEM-002 | 同一 T1 足以解释、处理和读取候选及所继承成果，固定机制与可变规则/内容边界清楚；机器升级和工具候选没有偷偷替换运行依据。 | 项目工具绑定、执行/读取记录、机制边界 |
| REL-SEM-003 | 候选中的约束和外部规范是当次真实采用的标准，显式换版的影响清楚；规则不因看到失败而静默降低，也不改旧发布或旧判断。 | 规则来源、换版选择、实际评审标准 |
| REL-SEM-004 | 模型、原生 view、文档、实现与关系共同解释发布成果，不隐藏失败、断链或剩余问题；图和文件齐全不是工程主张充分的证明。 | 选定内容、完整追溯、正反证据 |
| REL-SEM-005 | 早期阶段证据能以其原输入、规则、环境和范围支持当前候选，差异经分析；不能把旧检查标成最终构建执行，也不能因内容相似无理由继承。 | 证据原选择、差异、复用/补验理由 |
| REL-SEM-006 | 最终发布理由引用确定候选，说明已满足内容、剩余问题、限制与准许工作；用户例外仍保留失败事实，不能证明缺失依赖或封存效果已存在。 | 发布/用户决定、候选、例外及限制 |
| REL-SEM-007 | 候选内容、决定和发布清单的身份分离足以重建实际顺序，无循环自证；封存核对能发现内容或依赖替换，开发区并行编辑不会改变候选。 | 候选/决定/清单关系、核对观察 |
| REL-SEM-008 | 冻结边界足以保证发布独立可读，含相关工程资产、规则、关系、证据及所需工具/上游版本；共享对象和外部材料实际可恢复，可变目录或链接不足以支持。 | 依赖闭包、实际读取、保留方案 |
| REL-SEM-009 | 封存后的核查评价成功是否有真实内容与访问依据，失败/部分完成/未知结果保留并核查；发布批准本身不能证明已完成保存或提供只读访问。候选评审不预写后置成功事实。 | 封存效果、读取验证、故障恢复 |
| REL-SEM-010 | 验证工具隔离能力时，实际 R1 后修改约束、模型/view、文档、代码和关卡结果再发布 R2，R1 内容/决定/依赖不变且原 T1 可读，覆盖保存拒绝、损坏与渲染不覆盖。普通项目依据固定工具的能力证据核对本次边界，不将未来 R2 作为首次 R1 的批准前提。 | 工具能力 R1/R2 实证、本项目选择、拒绝/损坏/渲染验证 |
| REL-SEM-011 | 增长与清理策略只保留本次所需依据又不丢依赖，不强制每个发布复制所有历史；归档/退役/撤回不破坏已有发布，说明在对象之外追加。 | 共享内容、引用保留、归档/撤回责任 |
| REL-SEM-012 | 工具自身发布将候选机制交付为新 T2，当前 T1 及既有项目/发布保持原依据；初始引导有有限来源与真实验证，不用工具自我声明代替隔离证据。 | 工具候选、实际验证、T1/T2 项目绑定 |

## 出口与返工

AGENT 形成绑定候选的 `pending/approved/rework/rejected` 建议及实际发布决定；批准限定特定候选的封存，不是封存完成事实。核心模型/实现/证据不足时沿影响回到相应阶段；依赖或发布准备不足时补材料并组织新候选。当前决定变化写开发记录，旧发布保持只读。

封存后的完整性与隔离核查仍保存实际结果。损坏时报告损坏和影响，不把外部更改采纳为原发布的新版本；修复或替代需要有范围的处理记录及新的对象选择。交付、运行和逐 Wish 完成依据各自契约判断。

## 判定示例

充分：发布引用原始阶段证据及其输入/规则，AGENT 说明未变范围的复用依据；R1 后规则和代码演进产生 R2，实际对照显示 R1 与依赖不变且可由 T1 读取。

不足：R1 的文件路径仍指向开发区，用户改关卡后旧发布展示也随之变化；或为压缩历史删除 R1 所需旧规则，或以最终决定存在就推断发布文件已保存。
