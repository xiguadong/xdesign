# 发布候选与不可变成果：语法校验规则

规则集版本：0.1。状态：目标约束草案。日期：2026-10-12。

## 适用范围、依据与输入

适用于项目发布的范围选择、候选快照、结构检查、AGENT 发布决定、核对、封存及只读访问，也适用于工具项目交付下一工具版本。依据[整体架构 0.2](../../../design/workflow_mbse_architecture.md)“一次发布的执行过程”“持续增长的项目资料”“工具项目自身的开发”，遵循[公共协议](../README.md)、[模型](../model_traceability/syntactic_constrains.md)和[运行记录](../workflow_execution/syntactic_constrains.md)规则。

这是发布操作的跨阶段约束，不新增 V-model 阶段，不改变 `Operations handover` 等固定关卡的位置。现有 `OperationsBundle` 提供交付产物基础，候选/发布身份与不可变存储是架构 0.2 的目标能力，不声明当前 SysML 模型或仓库已经实现。

输入为项目固定工具 T1、明确的用户约束版本、所选 Wish/部件、模型及原生 view、文档/代码/构建、实际证据与决定、继承发布及必要依赖。允许在开发区建立候选，追加真实检查与决定，核对并创建新的不可变发布；已发布对象只读。输出为候选清单、检查/判断/决定、封存结果、新发布身份与只读读取诊断。

## 产物组织

候选与发布清单可采用架构中的 `release.json` 或选定契约明确的等价格式，记录逻辑身份、内容摘要、文件/依赖清单、工具和约束选择、候选/决定关联及继承发布。格式不冻结尚待设计的具体字段名。发布说明和验证记录默认 `<scope>_release_review.md`、`<scope>_release_verification.md`；`releases/R1/` 等为职责示意，实际存储可使用共享不可变内容并保持访问边界。

## 规则

| ID | 约束与判定方法 | 诊断位置 |
| --- | --- | --- |
| REL-SYN-001 | 发布范围列出 Wish、项目部件及选定成果，收集模型/规则/资源与证据所需依赖；每项具有身份、确定版本或内容摘要与可恢复内容。可变路径、分支名或网页地址不能单独满足固定选择。 | 范围清单、依赖清单、内容定位 |
| REL-SYN-002 | 工具选择与项目初始化绑定一致，固定 V-model、公共元模型、编译解析、渲染、追溯及依赖能恢复。共享工具发布可引用，不为每条 Wish 复制；T2 候选不能替换本项目执行 T1。 | 项目锁定、工具发布身份及依赖 |
| REL-SYN-003 | 保存当次采用的用户约束 SysML、文档规范及外部规则确定内容，局部引用含章节标识；规则换版明确，旧检查的规则选择另行保留。 | 用户规则、外部快照/章节、版本 |
| REL-SYN-004 | 候选有唯一身份和确定内容标识，包含模型、view、文档、实现、关系与已选证据依赖；内容标识不包含尚未产生的最终发布决定，避免决定引用其自身输入的循环。 | 候选身份、内容清单、摘要计算边界 |
| REL-SYN-005 | 实际结构检查针对候选的确定选择执行，记录工具、规则、主体、时间、结果和诊断；语义判断引用同一候选。早期阶段证据保留各自实际输入/规则，不重标为最终内容执行。 | 本次检查、早期证据及适用性记录 |
| REL-SYN-006 | 最终发布决定记录主体/kind、授权范围、候选身份、结论、理由、证据及允许的封存工作；用户替代决定绑定同一候选并保留原判断与事实。发布责任按 workflow 配置，不移动固定 V-model 关卡。 | 发布决定、候选引用、授权及替代关系 |
| REL-SYN-007 | 封存前核对候选标识、所审内容、依赖与当前决定一致，所有所需内容可读；更换内容/依赖建立新候选及相应检查判断。开发区无关编辑不改变已固定候选。 | 封存前核对、内容差异、新候选 |
| REL-SYN-008 | 封存使用新的发布身份，清单关联候选、最终决定/用户决定、成果、工具、规则及继承发布；保存结果明确区分准备、失败、不确定和成功。成功前不能以发布标签暴露虚假完成对象。 | 发布清单、封存尝试与结果 |
| REL-SYN-009 | 成功发布使用独立不可变存储与只读访问，模型/view/文件/决定/证据不得被日常保存覆盖；共享内容对象被编辑时必须产生新身份。 | 发布路径、保存拒绝、内容对象 |
| REL-SYN-010 | 读取发布验证内容与依赖摘要，并使用该发布绑定工具/模型/view；外部修改报告损坏或缺失，不接受为同一发布的新内容。 | 读取核对、工具选择、损坏诊断 |
| REL-SYN-011 | 需交付的渲染文件随包冻结；重编译/渲染/查询产生的临时表示写缓存，不能覆盖发布文件或改变模型、约束和决定。 | 包内展示、缓存位置、写入结果 |
| REL-SYN-012 | 继续开发只读继承 R1，后续模型、规则和新决定写开发区并封存为 R2；撤回/替代说明追加在原发布之外。存在继承关系不能把 R1 恢复为可编辑状态。 | 继承发布、开发选择、外部说明 |
| REL-SYN-013 | 发布保留所需依据的完整依赖而非全部临时草稿/开发历史；不可变共享对象只存一份也须在已有发布需要时保持可读。清理/归档不得破坏发布引用。 | 依赖闭包、保留清单、共享引用 |
| REL-SYN-014 | 失败或结果不确定的封存保留实际效果并先核对，再以原尝试身份去重/恢复；不得盲目重试创建重复发布或把部分保存标为成功。 | 封存恢复、外部效果、发布身份 |

## 出口与失败处理

候选结构合规后交由[语义评审](semantic_constrains.md)，有效发布决定允许封存特定候选；成功封存后才产生只读发布成果。检查/判断不足时补材料或新候选，保存失败时记录真实结果并恢复，不能宣称发布成功。用户可改变开发决定但不能更改已发布包或补造封存结果。

本次成果后续用于交付、运行及验收时，按对应阶段独立评价适用性；一次发布不自然证明所有 Wish 完成。工具项目的 T2 是新的交付成果，既有业务项目和其发布仍使用 T1。

## 判定示例

合格结构：候选 C1 固定 T1、约束 U1 和选定成果，D1 引用 C1；R1 清单关联 C1/D1 与依赖。开发修改为 U2、模型 v2 和新决定后封存 R2，R1 的读取与摘要仍完全相同。

不合格结构：候选摘要包含尚未生成的最终决定；或 R1 只引用 `development/current.sysml`；或保存新决定时覆盖 R1，或封存仅完成一半却返回已发布。
