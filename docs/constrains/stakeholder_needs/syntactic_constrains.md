# 利益相关方需求：语法与阶段合规约束

规则集版本：0.1。日期：2026-10-12。状态：依据当前架构新增的目标约束，检查器实现状态不由本文声明。

## 适用范围、依据与输入

适用于初始 V-model 的 `stakeholderNeeds` 阶段及其 `Needs review` 审查材料。本文中的语法层包括 SysML 语言解析、名称与类型合法性、文件和文档结构、阶段产物、关系以及实际记录存在性；工程充分性见 [semantic_constrains.md](semantic_constrains.md)。规则适用性、选定版本和通用结果表达见 [总说明](../README.md)。

依据为 [整体架构 0.2](../../../design/workflow_mbse_architecture.md) 的“生命周期中的内容分类”“开发区的三类模型”“用户约束如何演进”“两个区域的操作边界”，以及 [V-model](../../../v_model_agents.sysml) 的 `NeedsAgentBehavior`、`stakeholderNeeds` 和 [产物模型](../../../wish_to_product.sysml) 的 `Wish`、`NeedsSpec`、`NeedsBundle`。`NeedsSpec::specVersion = "1.0"` 是现有模型的产物契约版本，与本文规则集的 0.1 分别记录。工具机制属于项目初始化时绑定的工具发布，阶段契约和用户规则版本不得以日常编辑替换其 V-model 或公共元模型。

输入为原始 Wish 的稳定身份和保留内容、选定 Wish 版本、增量与尝试范围、工作上下文、项目边界、已存在的上游基线、项目初始化绑定的工具发布及固定依赖、本次显式选定的用户约束版本以及本阶段执行者与关卡 AGENT 配置。采用 `ContractedVModelDevelopment` 时，上游还应包含其选定的 `feasibilityBaseline`；首轮引导材料的来源和局限必须可定位。读取已有项目发布作为输入时保留发布身份与确定内容。

## 允许工作与产出

允许在项目开发区澄清 Wish、记录利益相关方与使用角色、描述预期用途和场景、建立需求意图及使用确认/验收意图、列出约束/假设/开放问题，并更新独立 Wish 模型及其原生 view。用户规则 SysML 和文档规范可以在开发中形成新版本，后续尝试显式选择；固定工具机制不随之变化。原始提交的事实内容继续由记录来源保留，工程解释形成独立可追溯产物。已有发布只读继承，更新后的成果进入开发资产及后续新发布，见 [项目发布语法约束](../project_release/syntactic_constrains.md)。

必须提交包含实际内容的需求意图模型、Wish 解释、使用场景、验收意图/标准、开放问题清单及其版本清单。建议文档名为 `wish_interpretation.md`、`use_scenarios.md`、`acceptance_intent.md`、`open_questions.md`；对应文件的实际目录与 Wish/增量归属由阶段契约固定。可以合并为一个文档，但审查清单必须提供各部分的稳定章节定位。空的开放问题清单应明确写“无已识别开放问题”。

## 出口与返工

结构检查通过表示本次已执行规则满足，可以提交 Needs review；它不构成放行。实际推进需要同一材料选择上的语义判断及当前有效开发决定，并确认项目绑定流程的运行前提。正常通过只允许进入系统需求阶段，约束修订不改变固定关卡。

缺失材料、不可解析引用或结构错误在开发区修正并重新检查。来源 Wish、上游范围或显式采纳的用户约束变化时，重建受影响材料选择，按固定流程进入影响评估并从最早受影响位置返工。用户的范围内例外形成新的开发决定，原事实和已有发布不变；不可读取输入等运行前提仍需满足。工具绑定不一致须修复运行配置；既有项目的工具升级另行设计迁移，不能作为普通返工切换。

## 合格与不合格例子

- 合格：`W001` 的原始提交记录与 `W001` 模型解释各有版本，`SCN-01` 描述暂停后恢复场景，`ACC-01` 引用该场景并记录拟在验收阶段由指定主体检查恢复位置；实际语法检查记录绑定本次源版本，Needs review 决定允许 `systemRequirements`。
- 不合格：只声明 `out item produced : NeedsBundle`，没有真实意图/场景材料，却填写 `syntaxPassed = true`、`released = true`。该声明不能满足产物存在和实际记录约束。
- 结构合格但仍待语义判断：所有场景字段完整、引用可解析，只包含成功路径。是否需要补充失败或异常场景由本阶段 AGENT 根据适用范围判断，不因字段齐全自动放行。
- 不合格：项目绑定 `T1`，阶段因本机安装 `T2` 而使用新版元模型检查，并把更新后的场景与用户决定直接写入 `R1`；工具发布及已发布内容均越过了日常开发的写入边界。
