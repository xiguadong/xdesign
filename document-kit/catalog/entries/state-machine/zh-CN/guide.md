# 生命周期状态机编写指南

本条目用于把生命周期中的行为差异形式化为状态、事件和转换规则。作者应证明每个状态都有独立的行为意义，并说明非法事件、监护失败、恢复和终止时历史如何处理，而不是为每个变量值机械增加状态。

## 问题、边界与论证方法

状态分析应同时列出合法转换和被拒绝或忽略的事件。监护条件必须可由给定状态和环境判定，转换后的不变量必须保持明确；恢复过程需要区分成功、失败和再次故障，终止状态则要说明资源与历史语义。

字段示例：`guards = "tick 仅在 Sampling 且探头正常时接受，reset 仅在 Fault 且自检成功时接受；其他组合均不得改变状态或历史。"`。该示例说明字段应表达的可核查含义，而不是要求所有项目照搬这一对象。

## 结构、设计与证据

本条目保持既定章节、字段键和模型身份，不以论文式章节替代工程责任。六章依次给出目的、状态与不变量、事件与监护、转换与终止、恢复与约束以及验证映射。状态表或状态图必须与正文中的事件名称、监护条件和历史规则一一对应。

转换测试矩阵应覆盖合法路径、非法事件、监护失败、恢复成功与失败以及终止状态。计划用例用于证明验证覆盖意图，只有实际事件日志和状态观察才能支持生命周期结论。

## 视图、来源与限制

多个状态和事件驱动转换适合状态图；状态较少时，状态转换表往往更便于检查监护条件和禁止路径。任何替代表达都应保留终止、恢复和历史不变量。

来源标识为 ARC42, GITHUB-DOCS；这些标识仅用于追溯写作方法和信息需求，不构成对虚构示例的实现、测试或评审证明。评审应关注状态是否具有行为区分、非法事件是否被定义、恢复是否可能伪造样本，以及图表是否遗漏约束。
